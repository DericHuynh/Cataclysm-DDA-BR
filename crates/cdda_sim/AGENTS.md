# cdda_sim

## Purpose
Owns gameplay systems and the canonical headless simulation runtime. The graphical app, headless scenarios, and future replay driver must use the same schedule rather than reproducing its wiring.

## Ownership
- `runtime/` owns the simulation driver, clock adapter, lifecycle types and test helpers.
- Gameplay systems live under `actor`, `ai`, `intent`, `activity`, `combat`, `crafting`, `equipment`, `inventory`, `item`, and `noise`.
- Shared domain components live in `cdda_components`; local execution state may live here.
- Dependencies include `cdda_components`, `cdda_core_types`, `cdda_catalog`, and the workspace-internal `cdda_htn` planner core. Data/raw schemas are dev-dependencies for fixtures only; runtime has no input, asset, or renderer dependency.

## Local Contracts
- **Canonical wiring:** `runtime::SimulationPlugin` installs gameplay plugins/resources and the persistent `SimulationTurn` schedule. It orders `GameSet::Input → Sim → Render` in outer `Update`; only `drive_simulation` runs in the Sim slot. Register authoritative systems in the owning logical turn/action/activity schedule, not `Update`. World adapters extend `SimulationRefresh`/`SimSet::SpatialUpdate` after commits, including commands between world ticks.
- **Time:** one logical turn = one game second, matching definition `Time`. `GameTime` is in `cdda_components::sim`. `SimClock` is ONLY the optional real-time wall accumulator, default 100 ms pacing; it is fail-closed, rejects a zero step, retains bounded catch-up backlog, and clears wall debt while paused.
- **Driver:** `SimulationControl` defaults to `TurnBased`: living PlayerData/DevPlayer actors reuse positive moves across input frames; other actors wait until player moves are exhausted. Idle player input also holds NPC activities and refresh work. Commands at exhausted budgets or ongoing player activities request the next world second; worlds without a player retain action/activity-driven turns. `Manual` advances only via queued `request_steps` or `step_simulation`; `RealTime` consumes wall time. `max_steps_per_update` bounds work without dropping backlog. Explicit requested steps survive pause. `step_simulation(&mut World)` returns false if paused or an installed `AppState` is not `InGame`; headless apps may omit AppState. A raw `world.run_schedule(SimulationTurn)` bypasses the driver gate and is not the supported stepping API.
- **Phase order:** TurnTick → Effects → Healing → Bionics → Morale → Temperature → Vision → Spawning inside `SimulationTurn`. `SimulationIngress` translates pending craft requests and consumes legacy item moves before arbitration. IntentDeclare → IntentResolve run inside SimulationAction; typed activity work/completion run inside SimulationActivity. `SimulationRefresh` runs inventory bookkeeping then spatial synchronization after commits. Ingress/arbitration/refresh may run without a world tick while player moves remain. Explicit/manual/realtime steps always grant one world turn and use AP order without waiting for external player input.
- **Shared AP budget:** after world phases, the driver selects the highest-AP living actor (SimId/Entity stable tie-break), dispatching SimulationAction or SimulationActivity. Craft ticks consume all available AP, including finishing overshoot; aim/reload use at most 100 AP per selection. Reading/waiting/interaction advance at most one second and spend the available budget; partial final seconds truncate proportional cost, including zero-cost completion. Activities never incur debt; discrete actions may. Any remainder after non-craft completion is available for queued actions. Lifecycle progress counts even when AP cost rounds to zero. Unsupported/rejected/no-progress actors park; each actor is bounded to 64 selections per dispatch, keeping unused AP. A subsequent external player command may resume that budget. The total bound scales with initial living-actor count, so large groups are not cut off at 64 actors.
- **Combat data:** queries/formulas use MeleeCapability independently of DodgeDefense and IntrinsicArmor. CombatStats remains a non-component adapter input only. Native melee/ranged attack execution, equipment protection and morale-derived modifiers are still unimplemented; never report these stubs as successful actions.
- **Activity lifecycle:** one ActivityProgress/type pair per actor; malformed multiple types cannot spend work. Typed systems fetch only the selected actor. interrupt_activity removes all activity tags/progress and retains the saved craft item. Resume validates actor/ownership/access and restores remaining work; completion requires finished work and a living owner. Inaccessible/vanished craft targets interrupt before AP spend. Suspended/dead activities alone do not wake turn-based time. Craft completion uses a persistent message cursor without draining other subscribers' notifications. InterruptActivity/ResumeCraft intents take precedence over work for the selected actor, report correlated outcomes and charge no setup AP; resume work spends the available budget afterwards. Resume failures preserve the existing activity; resuming an already finished craft reports its output result.
- **Intent commit:** `resolve_intents` is an exclusive sequential world commit: validate live state, commit mutations/AP, then publish matching terminal outcome. Subsequent requests see committed positions, ownership and AP. Equal AP orders by SimId ascending (identified entities first), with Entity bits fallback for untagged fixtures/duplicate IDs. Request IDs are allocated in sorted order; replay requires unique SimIds.
- **Action validation:** `inventory::transfer::apply_inventory_action` is the shared transactional boundary for item actions. Move requires an existing position, nonzero one-tile offset and a non-overflowing, unoccupied destination (ECS `Solid` entities; local terrain not yet represented). Pickup/Wield/Drop/Stow/Transfer validate live exclusive location, ownership-chain/cycle safety, same-z Chebyshev ≤ 1 reach for ground items, HandCount for wielding (missing hands = none), and the exact-tile floor cap for drops; each charges 100 AP once after validation. Move/Wait/Pickup/Wield/Drop/Stow complete; MeleeAttack/UseItem/Reload/StartRead/Interact remain unsupported on the intent path (Failed, no AP). Rejected/Failed charge no AP. A despawned actor has no outcome component, but its rejection is counted. Capacity validation projects the whole counted stack into the destination and all ancestor pockets before mutation; volume/weight includes existing nested contents, rigid shells hide interior volume but retain mass. Checked arithmetic rejects overflow. Automatic storage tries stable-ordered fitting pockets and never escapes a full modeled inventory through loose storage. Transfer permits owned or reachable unowned containers and rejects other actors' ownership. Unknown dimensions retain legacy zero defaults, never a weight-check bypass. Sealed ancestors reject access. Specialized pocket types, PocketRestriction, non-solids and charge-based dimensions fail closed until supported. Body pockets remain deliberately generous compatibility storage.
- **Planner submission:** BT/GOAP never replace an existing ActionIntent. HTN yields to an external command and discards its old plan state, preventing a lifecycle outcome from advancing that plan.
- **Submission is not completion:** terminal `ActionOutcome` persists and consumers correlate request IDs. HTN never commits predicted effects; the simulation is authoritative. Planner costs are estimates only.
- **UI boundary:** do not match `GameAction`/read `InputAction` in simulation systems. Screen adapters live in `cdda_render::render::input` and declare ActionIntents for wield/stow/pickup/drop and examine resume (no AP/relationship/`ItemMoveEvent` bypass). StartCraft is resolved transactionally and reports the start separately from work completion. PendingCraft is a legacy menu mailbox translated before arbitration, never a direct ingredient-consumption path. Remaining creation work: dev spawn and direct item/craft-result placement. Item-examine input is owned by cdda_render and has no shell mutation bypass. Explicit transfers and legacy move messages share validation; birth/output placement still needs a capacity policy.
- **Legacy movement:** ItemMoveEvent is a whole-stack request, not a committed notification. Its adapter requires a matching live source/count, infers a living actor from ownership/destination, uses apply_inventory_action, and emits ItemMoveResult. Partial stacks, stale requests and actorless relocation reject without cost. Persistent message cursors process each request once; commits are synchronous. Native callers should use ActionIntent::Transfer.
- **Stacks/letters:** assign_invlets_system is a typed bookkeeping system: reserve unique new letters locally before deferred inserts; never merge/relocate/despawn. Explicit merge_stacks requires colocation, matching identity/dimensions/damage and native snapshot identity; rejects self, stateful containers, independent child lifetimes and arithmetic overflow. Checked legacy charge totals are summed. Merge is not a transfer and charges no AP.
- `state` and `test_utils` lib-root aliases are deprecated; use `runtime::*`.

## Compatibility gate

The current native runtime is not player-visible-equivalent to master; see
`docs/master-semantics-audit.md` from the repository root. The shared budget
contract above describes BR. Neutral craft spending, partial TIME rounding and
player command/world-time boundaries now have master-derived headless fixtures.
Crafting modifiers/reach/eligibility, item handling costs, detailed world-phase
ordering and other activity effects still prevent a general parity claim.
Use activity-specific master code for parity fixtures, not generic budget rules.
Resolve supported-family semantic differences before expanding gameplay.

## Work Guidance
- New behavior goes in its owning subsystem; register it through SimulationPlugin or the subsystem plugin on the canonical schedule.
- Entity relationships maintain reverse links, not gameplay invariants. Use explicit validating operations for transfers, merges, equipment and costs. Reinsert immutable relationships via World or Commands; do not mutate their fields in place.
- Explicit phases/transactions own simulation causality. Events are appropriate for notifications and bounded reactions, not a substitute for action commit ordering.
- Use real persistent App/schedule tests for timing, pause, message cursors, deferred visibility and production wiring. `TestBed::run_system` recreates a system each call and is only an isolated-function helper.

## Verification
- `cargo check -p cdda_sim`.
- `cargo nextest run -p cdda_sim` (fallback cargo test if nextest unavailable).
- `cargo nextest run -p cdda_sim --test simulation_schedule_test --test intent_transaction_test --test htn_integration_test` covers production stepping/frame partition/pause/calendar, sequential commits and the planner integration.
- Workspace integration: `cargo check -p cdda_app` and `cargo nextest run --workspace --exclude cdda_app` (app default dynamic-link test loader is environment-sensitive).
- Cargo discovers top-level `tests/*.rs` only; the migrated nested suites are wired through the `migrated_{actor,combat,inventory}.rs` aggregators (302 restored tests, 83 pre-existing `#[ignore]` stubs). The discovery guard in `migrated_actor.rs` fails if aggregator modules drift.

## Child DOX Index
- `src/runtime/` — `plugin.rs` canonical SimulationPlugin/SimulationControl/SimulationMode/step_simulation, player-budget continuation and separate ingress/refresh schedules; `clock.rs` real-time accumulator; `state.rs` AppState/StartupConfig; `test_utils.rs` isolated TestBed.
- `src/intent/` — stable collection, live sequential validation/commit, correlated outcomes.
- `src/actor/` — AP grant, independent combat-capability registration, effects, movement, healing, bionics, morale, temperature and vision (some physiology remains stubbed).
- `src/ai/` — per-marker BT/GOAP placeholder producers and real HTN driver before intent collection.
- `src/ai/htn/` — kernel registry, actor observations, parameterized JSON compound compiler and request/result execution adapter over `cdda_htn`; built domain and ItemCatalog are an immutable resource pair. Startup/reload publication and plan-generation invalidation still need full integration.
- `src/activity/` — selected-actor typed work systems and completion in SimulationActivity; lifecycle.rs owns interruption/preflight and enforces one activity type.
- `src/crafting/` — ingredient reservation, synchronous commits, pending craft start/completion and revision notifications. Availability uses shared recursive inventory traversal and excludes sealed ancestors; legacy same-OMT ground reach is retained with unowned/live-source filtering. CraftState/CategoryIndex and OnEnter menu indexing belong to cdda_render. Validate output/count/work and all ingredient slots before consumption; backtrack alternatives across shared requirements. Prepared output snapshots survive reload; failed legacy completion retains the craft. Native StartCraft and the legacy menu ingress share intent arbitration; saved craft work is authoritative for resume/ticking. Direct do_craft remains an explicit instantaneous test/dev helper, outside gameplay budgets.
- `src/inventory/` — recursive ownership traversal; transfer.rs transactional item actions and legacy request validation; capacity.rs checked projected nested load/access; merge.rs explicit colocated stack commits; systems.rs legacy request consumption/results, invlet bookkeeping, bins and compatibility read helpers. Partial stacks, special pocket restrictions and direct creation placement remain outside the counted-solid transfer slice.
- `src/combat/`, `src/equipment/`, `src/item/`, `src/noise.rs` — combat/equipment operations, type registration, noise functions. `item/spawn.rs` prepares explicit capability snapshots and creates populated runtime items/native pocket entities; never clone IsDef or arbitrary relationships.
- `tests/` — top-level domain tests plus `simulation_schedule_test.rs`, `intent_transaction_test.rs`, `inventory_action_test.rs`, `inventory_capacity_test.rs`, `activity_budget_test.rs`, `htn_integration_test.rs`, `inventory_traversal_test.rs`, and the `migrated_{actor,combat,inventory}.rs` discovery aggregators.
